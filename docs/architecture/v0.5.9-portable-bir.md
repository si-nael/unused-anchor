# v0.5.9 Portable Execution Authority: BIR (Gate C) and Causal Conformance (Gate D)

Recorded: 2026-11-16

Status: completed bounded `v0.5.9` Gate C and Gate D release; scope selected by the author on 2026-11-16

## Objective

Bubble is meant to construct and actually execute one universe (AI-20261116-001). Its execution meaning therefore cannot live in TypeScript object layout, JSON serialization, or the collation library of one host. Gate C of the 5.x-to-6.x boundary requires one implementation-independent semantic graph for the stable core before a native backend may carry execution authority (D-113, D-114, Q-027).

This candidate closes the first vertical slice of that gate: the executable causal kernel (`bubble-anchored-causal-program.v2`), through which every bounded world path currently runs, gains a canonical binary semantic graph that a second implementation can read, plus the oracle corrections that make the graph's unordered collections genuinely unordered.

## 1. The host was an unstated part of world meaning

Before any byte format could be fixed, two facts had to change.

**Host collation decided evidence order (B-054).** The kernels sorted with `String.prototype.localeCompare` at 58 call sites and with UTF-16 `Array.prototype.sort` elsewhere. ICU collation places `_` before `-` before `.`, orders `:` before digits, and groups case, so `trace:1:x` sorts before `trace:10:x` under collation but after it in code-point order. A backend reproducing that evidence would have had to emulate one host's ICU tables. Canonical order is now Unicode code-point order everywhere (`compareCanonicalStrings`, D-135).

**Declaration order leaked into causal evidence (B-055).** A permutation experiment reversed every collection of every canonical causal fixture, one at a time, and compared the runs. Most collections were already invariant. Four were not:

- initial sea coupling of distinct worlds emitted sequential trace ids in world declaration order;
- the trace listed a law's or intervention's field effects, and a commit's fields, in authored order;
- anchor-identity evidence for each continuation and intervention outcome followed anchor declaration order (visible only in the 7-world compiled connected universe);
- a law could list the same committed field twice, so reading that list as a set could have changed its meaning.

Each of these is causally concurrent or keyed structure, so the oracle now iterates it in canonical order, and the validator rejects duplicate committed fields (`CKW105`). After the correction, reversing any set-classified collection of any canonical fixture leaves the run identical apart from the host object digest.

## 2. BIR v1

The normative byte-level contract is [../reference/bubble-ir.md](../reference/bubble-ir.md). In outline:

- a node algebra of structural booleans, arbitrary-precision integers, UTF-8 strings, sequences, sets, records, maps, and exact rationals, booleans, and symbols, with exactly one encoding per node;
- schema-directed lowering that classifies every collection as ordered or unordered on the basis of the permutation evidence, keeps open vocabularies as text, and refuses to drop an unknown field or normalize a non-canonical value;
- a versioned envelope of named sections with critical and non-critical flags and a SHA-256 trailer, preserving unknown sections byte for byte and refusing to execute a document with an unknown critical section;
- three separated identities: semantic graph identity over critical sections, canonical storage identity over all bytes, and backend program identity of the host object.

Rust, Node, CPU layout, and the byte format itself remain outside Bubble ontology. BIR is the portable meaning a backend must reproduce, not the world.

## 3. Closed evidence

- All eight canonical causal programs round-trip: three causal JSON worlds, two persistent-program kernels, two strict `causal bubble` sources, and the 7-world compiled endogenous connected universe. Each decodes, re-encodes byte for byte, lifts to a valid program, re-encodes from the lifted program to identical bytes and semantic identity, and executes to a run identical to the source run except the host `programDigest`.
- Reversing every set position of every fixture leaves bytes, semantic identity, and execution unchanged. Reversing an ordered position (intensional domain axes) changes semantic identity.
- A non-critical extension changes storage identity but not semantic identity, survives re-encoding byte for byte, and does not affect execution. An unknown critical section is preserved and makes the document non-executable.
- The decoder rejects a corrupted trailer, foreign magic, a future major version, trailing bytes, non-minimal integers, unsorted or duplicate set members, unsorted record keys, non-reduced rationals, malformed UTF-8, and unknown tags. Lowering rejects unknown host fields, non-canonical exact values and decimal strings, duplicate set members, invalid programs, and extensions that impersonate a core section.
- The ordinary evidence cycle now runs strict `connected-fields.causal.bubble` source through BIR (`data/bir/connected-fields.bir`, 6,241 bytes) and executes the BIR document through the unchanged causal CLI, and `npm run verify` checks that the BIR run equals the source run.

## 4. Gate D: what a second backend must reproduce

A portable input is not yet an execution authority: a second backend also needs a portable expected output. Requiring it to reproduce the oracle's entire run would forbid optimization, because proof traces, evaluation subject ids, one evaluation linearization, sequential trace numbering, and host digests describe how the TypeScript oracle computed a world rather than what the world did. Gate D therefore fixes a portable outcome projection ([../reference/causal-conformance.md](../reference/causal-conformance.md), D-137):

- it keeps statuses, continuation sets, initial and final states, the event ledger with causes and field effects, causal edges and synchronous frontier layering, commits, lifecycle and transfer provenance, internal-event nonrealization, emergence, World-Will decision evidence, the resource-boundary verdict, and diagnostic codes;
- it drops oracle-plan artifacts and the host program digest.

Some evidence ids carry world identity (branch steps, lineages, transfer frontiers, commit and retirement state digests) and were derived from the oracle's undocumented stable serialization (B-056). That serialization coincides with the RFC 8785 JSON Canonicalization Scheme for the records involved, so the ids are kept and their derivation is now specified as SHA-256 over RFC 8785 (D-139). An independent RFC 8785 implementation in the tests reproduces branch, transfer-frontier, lineage, and retirement-residue ids.

A fixture is one BIR envelope whose critical sections are the program and the execution options (its input identity) and whose non-critical sections carry the expected outcome, a deterministic host-cost profile, and a label. The frozen corpus `data/conformance/causal/` holds eight canonical worlds and seven verdict fixtures: branch-, intervention-, and proof-budget exhaustion (`underdetermined`), World-Will-disabled all-anchors-cut autonomy, same-program internal-event nonrealization, a cut transfer anchor, and an unknown option target (`contradicted`). `npm run verify` checks the oracle against the committed corpus rather than regenerating it, so later oracle drift is detected; regeneration requires a recorded semantic decision.

The host-cost profile (D-138) counts work over the whole portable path (envelope decoding, lifting, execution): exact rational constructions and their largest bit length, intensional queries and materialized coordinates, predicate evaluations, law applications, branch-frontier candidates, realization and value copies, digests and hashed bytes, and BIR nodes and bytes decoded. It records no wall-clock time, is identical across runs, and is excluded from conformance. It profiles the four workload classes selected by Q-028: branch-heavy, exact-arithmetic, intensional, and persistent-lifecycle.

Gate D evidence:

- the reference oracle conforms to every committed fixture, and the corpus covers every defined case;
- an executor that changes one world value drifts with the exact path of the change;
- an executor that answers an exhausted branch budget by keeping the first branch drifts;
- an executor that rewrites proof traces, subject ids, trace numbering, evaluation order, listing order, prose, counters, and the host digest stays conformant;
- reordering every set position of a case's input reproduces the committed input identity and outcome identity;
- a tampered fixture is `invalid-fixture`, and an unknown critical section is `not-executable`.

## 5. Release Confirmation

On 2026-11-16 the author selected confirmation of `v0.5.9` at this scope (D-140). An independent adversarial audit preceded it and found six false surfaces inside the scope, all corrected before confirmation:

- the envelope ordered sections by length-prefixed encoding while the specification said raw name bytes, so a specification-following envelope was rejected and its semantic identity differed (B-057);
- family-coordinate parameters, classified as a set, were evaluated in declaration order and could change the outcome, and hard constraints, identity predicates, and objectives changed run listing when they had several members (B-058);
- the critical execution-options section was ignored by the BIR execution path and the causal CLIs, dropped by `encode-bir`, and could be demoted to non-critical without the checker noticing (B-059);
- evidence-id records did not state their array order, so branch ids were unreproducible from the outcome whenever set order differed from string order (B-060);
- the checker threw on malformed fixtures and executor failures, and the nesting bound exceeded what the oracle could process (B-061);
- anchor identity verdicts were absent from the outcome (B-062).

The corrections are listed in D-140. They change the format and the outcome schema, so the frozen corpus was regenerated once under that decision. Closed evidence after correction:

- whole runs, not only outcomes, are invariant when two or more members are reversed at every audited set position;
- a test derives the semantic identity from the specification text alone and decodes a specification-ordered envelope;
- `core.*` sections cannot be non-critical, and a document's own execution options are honored or conflicting caller options are refused;
- every evidence id is rebuilt from the decoded outcome alone, including when set order differs from canonical order;
- the checker classifies every failure without throwing, host-only fields a backend adds are ignored, and a term nested to the bound lifts and executes;
- an executor that falsifies anchor identity drifts at `anchorIdentity`.

TypeScript checking, all 266 unit tests, the BIR evidence cycle, the conformance check, and the complete `npm run verify` pass. Two audit observations were judged harmless and left: any minor version is accepted and is not part of semantic identity, and a safe-integer `-0` lowers to `0`. A runtime contradiction such as an unknown option target carries no diagnostic code, so its outcome records only the status.

## 6. Remaining Open After Bounded v0.5.9

- A second independent backend. The oracle checks itself against the frozen expectation, and the executor tests exercise the comparison, but no other implementation has yet reproduced the corpus from the specifications alone.
- Outcome schemas for endogenous materialization, persistence certificates, finite-demand certificates, and narrative programs, and portable replay records.
- A cost model with structural sharing, incremental evaluation, or compiled laws; the profile measures the current oracle only.
- Semantic sections for endogenous universe programs, persistent wrappers, and narrative programs; today they reach BIR only after compilation to a causal program.
- Identifying an omitted optional field with its stated default; BIR v1 preserves presence exactly.
- Canonical order of validator diagnostics.
- Whole-run and replay-record digests still use the oracle's stable serialization; portable evidence identity now exists only as the causal outcome identity.
- The B-053 identity semantics remain author decisions; BIR encodes the program, and the outcome records the oracle's current certificate behavior, not a settled rule.

Bounded v0.5.9 does not complete OB-013, start Rust, decide whether the 6.x entry condition is met, or change any v0.5.8 world claim.
